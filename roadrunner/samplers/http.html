HTTP Sampler

The http sampler executes HTTP requests using the JDK’s built-in java.net.http.HttpClient. Unlike ab, it exposes GET/POST/PUT/DELETE as sampler operation expressions, and every part of the request — URL, headers, and body — can be driven by a parameter source so each request differs.

Usage

roadrunner run -c <concurrency> -n <requests> http <options> '<expression>'

Arguments

Argument Description

<expression>

Sampler operation expression (required, positional) — see sampler operation expressions for the shared syntax. The HTTP sampler exposes four operations:

GET("<url>")
POST("<url>", "<body>")
PUT("<url>", "<body>")
DELETE("<url>")

Options

Option Default Description

--connect-timeout <ms>

10000

Connection timeout, in milliseconds

--request-timeout <ms>

10000

Timeout for a full request/response exchange, independent of --connect-timeout

--follow-redirects <policy>

NEVER

Redirect policy: NEVER, ALWAYS, or NORMAL (follow same-protocol redirects only)

--proxy-address <host:port>

Send requests through this proxy server

Example

roadrunner run -c 20 -n 1000 http 'GET("http://localhost:8080/api/health")'

Parameter sources

Combine with --parameters-source csv:file=<path> to vary each request from a CSV file. See Parameter sources for the general file format and typed columns. The HTTP sampler uses parameters in three ways: URL templating, headers, and body.

URL templates

${name} inside the <url> argument is replaced with the parameter named name, percent-encoded per RFC 3986 as a single path/query segment — a value can never span a path segment or query boundary, so it’s safe to substitute directly into either part of the URL:

id
1
2
roadrunner run -c 10 -n 100 --parameters-source csv:file=ids.csv \
  http 'GET("http://localhost:8080/api/orders/${id}")'

Each request substitutes the next row’s id — no distinction is made between templating the path (/orders/${id}) or the query string (?id=${id}); ${name} works the same in either position.

Headers

Any parameter named header:<name> is sent as the HTTP header <name> on every request:

header:X-Api-Key
secret-abc
secret-def
roadrunner run -c 10 -n 100 --parameters-source csv:file=keys.csv \
  http 'GET("http://localhost:8080/api/orders")'

Body

By default, POST/PUT’s second argument is sent as literal body text on every request. Prefix it with `@ to resolve the body from a named parameter instead, at request time:

payload
{"id":1}
{"id":2}
roadrunner run -c 10 -n 100 --parameters-source csv:file=payloads.csv \
  http 'POST("http://localhost:8080/api/orders", "@payload")'

If the payload parameter’s value is a java.io.File — i.e. a CSV column typed payload:file — the file is streamed as the request body instead of being read into memory as a string:

payload:file
order1.json
order2.json

If the referenced parameter doesn’t exist for a given row, that request fails with a clear error (e.g. No parameter named 'payload' for body reference '@payload') rather than sending an empty or literal "@payload" body.
