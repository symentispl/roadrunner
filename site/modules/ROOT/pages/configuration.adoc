= Configuration

Roadrunner is invoked as:

[source]
----
roadrunner [OPTIONS] <sampler> [SAMPLER_OPTIONS]
----

[#sampler-expressions]
== Sampler operation expressions

Some samplers (currently `http`, `jdbc`, and `neo4j`) take their positional
argument as a *sampler operation expression* rather than bare query text — a
method name followed by one or more double-quoted string literals:

[source]
----
methodName("literal", "literal", ...)
----

Each such sampler exposes one or more named operations; the expression
selects which operation to invoke and supplies its literal arguments. The
JDBC and Neo4j samplers each expose a single `query(...)` operation, so their
positional argument always takes the form `query("...")`; the HTTP sampler
exposes `GET(...)`, `POST(...)`, `PUT(...)`, and `DELETE(...)` — see
xref:samplers/http.adoc[HTTP Sampler], xref:samplers/jdbc.adoc[JDBC Sampler],
and xref:samplers/neo4j.adoc[Neo4j Sampler] for details. This syntax is shared
across every sampler that adopts it, so a future sampler exposing multiple
operations (e.g. `read(...)`/`write(...)`) uses the same expression grammar.

CAUTION: Always wrap the whole expression in *single* quotes on the shell
command line, e.g. `'GET("http://localhost:8080/")'` — every example on this
site does this. The double quotes belong to the expression syntax itself, not
the shell. An unquoted or wrongly-quoted `name(...)` is not just a syntax
error: in zsh, a word immediately followed by `(...)` is parsed as a glob
qualifier, which typically fails with a confusing error like `zsh: unknown
file attribute: h` or `zsh: bad pattern` — nothing to do with Roadrunner or
Java argument parsing.

== Load model

Exactly one load model must be chosen per run.

=== Closed-world model

All concurrent users loop continuously until the total request count is reached.

[cols="1,3"]
|===
| Option | Description

| `-c <n>`
| Number of concurrent users (required)

| `-n <n>`
| Total number of requests to make (required)
|===

Example:

[source,bash]
----
roadrunner -c 50 -n 1000 vm --sleep-time 5
----

=== Open-world model

New requests arrive at a fixed rate regardless of how long in-flight requests take.
This models real-world arrival patterns and avoids coordinated omission.

[cols="1,3"]
|===
| Option | Description

| `--rate <n>`
| Target request rate in requests per second (required)

| `--duration <d>`
| Test duration, e.g. `30s`, `5m`, `2h` (required)
|===

Example:

[source,bash]
----
roadrunner --rate 100 --duration 30s ab http://localhost:8080/
----

== Output and reporting

[cols="1,1,3"]
|===
| Option | Default | Description

| `-s <path>`
| timestamped dir
| Output directory for results CSV and report

| `-r <format>`
| `console`
| Report format. Built-in values: `console`, `html`
|===

HTML report example:

[source,bash]
----
roadrunner -c 10 -n 200 -r html ab http://localhost:8080/
----

== Latency correction

[cols="1,3"]
|===
| Option | Description

| `--pause-detectors vt,jvm`
| Enable pause-corrected latency recording. Accepts `vt` (virtual-thread scheduler pauses), `jvm` (GC/JVM pauses), or `vt,jvm` for both. Only supported with the open-world model.

| `--raw-latency`
| Force reports to use the per-event CSV histogram even when a pause-corrected `latency.hgrm` is present.
|===

[#parameter-sources]
== Parameter sources

Feed a dynamic set of parameters into each request (e.g. different SQL queries or URLs
per user) with `--parameters-source <type>:<key>=<value>`. See
xref:parameter-sources.adoc[Parameter sources] for the full syntax and the built-in
`csv` type, including typed columns.
